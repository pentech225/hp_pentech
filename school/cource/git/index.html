STEP 01
VSCodeを使えるようにする
インストール・基本操作・ターミナル
MISSION ご自身のMacBookにVSCodeを入れて、フォルダを1つ開き、ファイルを作って保存してみましょう。
公式サイトからVisual Studio Code（Mac版）をダウンロードし、インストールします。
アクセス先
code.visualstudio.com
ダウンロードした .zip を開き、出てきた「Visual Studio Code」をアプリケーションフォルダに移動してください。
作品を入れるフォルダを1つ作成します（デスクトップなど、どこでも構いません）。名前は自由につけていただけますが、英数字にしておくと後で困りません。
例
my-project
VSCodeを開き、そのフォルダを開きます。「フォルダーを開く」から、先ほど作成したフォルダを選んでください。
確認
左側にフォルダ名が表示され、その中にファイルを作れる状態になっていれば大丈夫です。
ターミナルを開きます。VSCodeには「ターミナル」が内蔵されています。
メニューから
ターミナル → 新しいターミナル
画面下に黒い入力欄が表示されます。これがターミナルです。これ以降、ほとんどの操作はここに文字を入力して行います。マウス操作よりも、こちらの方がずっと速く進められます。
STEP 02
Gitで履歴を残す
init / add / commit — 「セーブポイント」を作る
MISSION 作成したファイルを「セーブ」し、その記録が残ることを確認しましょう。

Gitとは何か

Gitは、ゲームの「セーブポイント」のようなものです。作業の区切りごとに記録を残すことができます。
失敗しても、前のセーブポイントに戻ることができるため、思い切って挑戦していただけます。

Gitをインストールする

VSCodeにはターミナルが内蔵されていますが、「Git」というソフト自体は別途インストールが必要な場合があります。お使いのパソコンに合わせて、下のボタンで手順を切り替えてご覧ください。

すでにGitが入っているか確認します。
ターミナルに打つ
git --version
確認
git version 2.x.x のように表示されれば、すでに使える状態です。下の「カレントディレクトリについて」まで読み飛ばして構いません。
表示されない場合は、インストールを促すダイアログが自動で出ますので、それに従ってください（数分かかります）。
それでもうまくいかない場合は、Homebrewというツールを使う方法もあります。
Homebrewでのインストール（任意）
# Homebrewが未インストールの場合、先にこちらを実行
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install git
git-scm.com/download/win から、Windows用のインストーラーをダウンロードします。
インストーラーを実行し、基本的にはすべて「Next」を押してそのまま進めていただいて構いません。
「Adjusting your PATH environment」という画面だけ、推奨（デフォルト）の項目が選ばれていることをご確認ください。
インストールが終わると、スタートメニューに「Git Bash」が追加されます。以降、これがWindowsでの黒い入力欄（ターミナル）になります。VSCodeの内蔵ターミナルの種類を「Git Bash」に選んでいただくと、これ以降の手順がそのままお使いいただけます。
確認
Git Bashを開いて以下を実行し、バージョンが表示されれば成功です。 
git --version

カレントディレクトリ（今いる作業フォルダ）について

ターミナルの操作は、常に「今どのフォルダにいるか」に対して行われます。これをカレントディレクトリと呼びます。VSCodeでフォルダを開いた状態でターミナルを起動すると、自動的にそのフォルダがカレントディレクトリになります。

操作コマンド備考
今の場所を確認するpwdMac／Windows（Git Bash）共通
中身を一覧表示するls共通
フォルダへ移動するcd フォルダ名共通
一つ上の階層に戻るcd ..共通
ホームディレクトリに戻るcd ~共通
パスの書き方の違い
🍎 Mac
/Users/自分の名前/Desktop/my-project
🪟 Windows（Git Bash）
/c/Users/自分の名前/Desktop/my-project
「C:\」が「/c/」になる点だけご注意ください
基本はcdを使わなくても大丈夫です
VSCodeで「フォルダーを開く」を使い、その状態でターミナルを開けば、すでに正しいカレントディレクトリになっています。cdが必要になるのは、ターミナルだけを単体で開いた場合や、別のフォルダに移動したい場合です。
このフォルダをGitで管理し始めます（最初の1回だけで構いません）。
ターミナルに打つ
git init
確認
Initialized empty Git repository のような表示が出れば成功です。
何かファイルを1つ作成します（例: index.html や index.py）。中身は何でも構いません。
例: index.html
<h1>はじめての作品</h1>
変更をGitに「これをセーブしたい」と伝えます（add）。
ターミナルに打つ
git add .
「.」は「今のフォルダの中の全部」という意味です。
セーブを確定します（commit）。メッセージには「何をしたか」を短く記入してください。
ターミナルに打つ
git commit -m "最初の作品を作った"
確認
以下を実行し、これまでのセーブ履歴が並んで見えれば成功です。 
git log
よくあるつまずき
「not a git repository」と表示される場合 → そのフォルダで git init をまだ実行していません。
commitできない場合（名前を尋ねられる場合） → 初回のみ、以下を1回実行しておいてください（ご自身の呼び名とメールアドレスで構いません）。
初回だけ
git config --global user.name  "自分の名前"
git config --global user.email "自分のメールアドレス"
STEP 03
GitHubに預ける
アカウント作成・リポジトリ・push
MISSION ご自身のGitHubアカウントとリポジトリを作成し、手元のセーブをGitHub上に送りましょう。

GitHubとは

GitHubは、ご自身のパソコンの中にあるGitの記録を、インターネット上に置いておける場所です。
世界中のプロのエンジニアも、ここに自分のコードを置いて仕事をしています。

github.com でアカウントを作成します。ユーザー名は今後ずっと使うことになりますので、変わった名前にしないようご注意ください（このユーザー名は、後で公開URLの一部になります）。
右上の「+」から「New repository」を選び、新しいリポジトリを作成します。名前は自由につけていただけますが、次のSTEP4で公開する場合は名前にご注意ください（後述します）。
手元のフォルダとGitHub上のリポジトリをつなげます（remote）。「Quick setup」の画面に表示されるコマンドをコピーしてお使いいただいても構いません。
ターミナルに打つ（URLは自分のリポジトリのもの）
git remote add origin https://github.com/自分のユーザー名/リポジトリ名.git
git branch -M main
git push -u origin main
確認
GitHubのリポジトリのページを開き直し、手元で作成したファイルが表示されていれば成功です。
よくあるつまずき
push時にログインを求められる場合 → パスワードではなく、GitHubの「Personal Access Token」か、初回に表示されるブラウザ認証をお使いください（先生と一緒に1回設定していただければ大丈夫です）。
「failed to push」（rejected）と表示される場合 → GitHub側に手元にない変更がある状態です。先生と一緒に git pull の意味を確認してからやり直してください。
STEP 04
作品を世界に公開する
GitHub Pages — pushしたら公開される
MISSION ご自身の作品に、誰でもアクセスできるURLをつけましょう。本日のゴールは、そのURLをスマートフォンから開き、ご自身の作品が表示されることです。

権限の話（大事）

やらないこと ⇔ やること
やらない
先生のホームページのサーバーに、生徒のパスコードやデプロイ権限をお渡しすること
やる
ご自身のGitHubリポジトリだけで完結して公開すること。先生のホームページには、ご自身のURLへのリンクを貼っていただくだけです

ですので、安心してご利用いただけます。ご自身の場所をどのように使っても、先生のホームページには一切影響がありません。

GitHubのリポジトリページで「Settings」タブを開きます。
左メニューの「Pages」を開きます。「Build and deployment」の「Branch」で main を選択し、保存してください。
少し待つと、公開URLが表示されます。形式は以下のようになります。
公開URLの形
https://自分のユーザー名.github.io/リポジトリ名/
何かファイルを修正し、もう一度セーブして送信します。
ターミナルに打つ
git add .
git commit -m "公開ページを更新した"
git push
確認
1分ほど待ってから公開URLを開き直すと、修正した内容が反映されています。これが「セーブ＝公開」の体験です。
先生のホームページとつなげたい場合
ご自身の公開URLが完成しましたら、先生にお伝えください。先生のホームページ側に「生徒の作品一覧」ページを作成し、そこから各自のURLへリンクを貼る形にいたします。この方法であれば、権限のやりとりは一切発生しません。

困ったとき

症状原因・対処
command not found: gitGitがインストールされていません。ターミナルで git --version を実行すると、Macが自動でインストールを促す場合があります。
commitできないgit config --global user.name / user.email を設定済みかご確認ください。
pushで止まるネットワークまたは認証の問題です。エラーメッセージの最後の行を先生にお見せください。
Pagesが404になる設定直後は反映まで数分かかる場合があります。Branchの選択が main になっているかご確認ください。
公開ページが更新されないgit push を実行し忘れていないかご確認ください。commitしただけでは公開先には反映されません。
エラーは失敗ではありません
エラーメッセージは「ここがおかしいですよ」と教えてくれているだけです。すべて読む必要はありません。一番下の行だけ読めば、たいていヒントが書かれています。
